# Tempa M1 — `tempa-core` + CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Binary `tempa` headless yang mengimpor konteks `.claude/` ke sumber netral, meng-generate file konteks untuk 5 agent, mendeteksi drift, memvalidasi kontrak dokumen + aturan task per PR, dan bisa dijalankan di Bitbucket Pipelines.

**Architecture:** Cargo workspace dengan dua crate. `tempa-core` (library) memegang semua logika sebagai fungsi murni di atas `&Path` repo; `tempa-cli` hanya parsing argumen (clap) dan mencetak `Finding`. Operasi git lewat `git` CLI (`std::process::Command`), tanpa libgit2. Satu fungsi `render` per agent dengan `match`, tanpa trait.

**Tech Stack:** Rust (edition 2024, `rust-version = "1.85"`), `serde` + `toml` (feature `preserve_order`) + `toml_edit` + `serde_json` + `sha2` + `globset` di core; `clap` (derive) di CLI; dev-dep `tempfile`.

**Spec:** `docs/superpowers/specs/2026-11-06-tempa-design.md` (bagian 3, 3.1, 6, 9, 10, 13-M1).

## Global Constraints

- Dependensi hanya yang tercantum di Tech Stack. Tambahan baru butuh alasan tertulis di PR.
- Header file hasil generate (Markdown), persis: `<!-- generated by tempa from AGENTS.md and .tempa/ — do not edit; run "tempa sync" -->`. TOML: baris yang sama diawali `# ` tanpa `<!-- -->`. JSON: tanpa header (identitas lewat `.tempa/lock.json`).
- File Markdown berfrontmatter (commands, agents, SKILL.md, `.mdc`): frontmatter tetap baris pertama, header diletakkan tepat setelah penutup `---`.
- Hash drift = SHA-256 hex dari isi dengan CRLF dinormalisasi ke LF.
- Semua penulisan file oleh tempa atomik: tulis `<path>.tempa-tmp` lalu `rename`.
- Default `tempa.toml` persis nilai spec 9.1, dengan `protected_paths = [".env*", "bitbucket-pipelines.yml", "tempa.toml"]` dan `[ci] base = "main"`, `skip_authors = ["renovate[bot]"]`, `docs_only_paths = ["docs/**", "*.md"]`.
- Kode `Finding` stabil (bahasa Inggris, dipakai CI/app); pesan untuk manusia dalam Bahasa Indonesia.
- Exit code CLI: `0` tanpa Finding ber-severity Error, `1` ada Error, `2` kesalahan pemakaian/konfigurasi.
- Agent v1: `claude`, `codex`, `gemini`, `opencode`, `cursor`.
- Jangan pernah membuat build status Bitbucket dari lokal (spec 3.1).
- Path di lock/finding ditulis relatif repo dengan separator `/` di semua OS.

## Review Focus

1. **Line ending CRLF di Windows** (`core.autocrlf=true`): file hasil generate yang di-checkout dengan CRLF tidak boleh dilaporkan drift; frontmatter dengan CRLF tetap ter-parse. → test di Task 3 dan Task 5.
2. **Nama/struktur command tidak biasa**: subfolder (`.claude/commands/db/migrate.md`), spasi dan non-ASCII (`review kode.md`) — path dipertahankan apa adanya di semua target. → test di Task 4.
3. **Clone dangkal di Bitbucket Pipelines** (base branch tidak ada / merge-base gagal): `tempa check` menghasilkan `git.base_unavailable` (Error bila `BITBUCKET_PR_ID` ada, Warning bila lokal), tidak panic. → test di Task 8.
4. **Menjalankan ulang** `tempa import` dan `tempa sync` dua kali: tidak ada section duplikat, tidak ada perubahan file kedua kali. → test di Task 5 dan Task 6.
5. **Repo baru / kosong** (tanpa `.claude/`, tanpa commit, tanpa remote): `init`, `import`, `sync`, `check` berjalan dan memberi pesan jelas, bukan error git mentah. → test di Task 10.
