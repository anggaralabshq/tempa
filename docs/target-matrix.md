# Agent target matrix (verified 2026-11-06)

Used by `tempa sync` (`crates/tempa-core/src/targets.rs`). Update this file and the code together when an agent's docs change.

| Source | Claude Code | Codex | Gemini CLI | OpenCode | Cursor | GitHub Copilot |
|---|---|---|---|---|---|---|
| context | `CLAUDE.md` = header + `@AGENTS.md` | native `AGENTS.md` | `.gemini/settings.json` → `context.fileName = ["AGENTS.md"]` | native `AGENTS.md` | native `AGENTS.md` (root and subfolders) | native `AGENTS.md` (CLI, cloud agent, code review, VS Code); no `copilot-instructions.md`, so it is not loaded twice |

## Notes

- `.agents/skills/` is read by Codex, Gemini, OpenCode and Cursor, so it is written once. OpenCode and Cursor also read `.claude/skills/`, so the same skill is visible from two places with identical content. Accepted: `tempa sync` keeps them identical.
- Claude: `Edit(...)` covers every file-writing tool (Write, MultiEdit). `/path` in project settings is relative to the project root, matching the root-relative `protected_paths` globs used in CI.
- Gemini CLI: for free-tier and Google One users, Gemini CLI was replaced by Antigravity CLI on 2026-06-18. This target still applies to paid and enterprise Gemini CLI users.
- Cursor commands: the commands docs page points to Skills, and Cursor offers a command → skill migration (`disable-model-invocation: true`). `.cursor/commands/` stays for now; move to skills when Cursor stops reading it.
- MCP env and headers: the source uses Claude's `${VAR}` syntax. OpenCode → `{env:VAR}`. Codex passes `env` and `http_headers` through: `KEY = "${KEY}"` → `env_vars = ["KEY"]`, header `"${VAR}"` → `env_http_headers`, `Authorization: "Bearer ${VAR}"` → `bearer_token_env_var`; any other form (e.g. `DB = "${DB_URL}"`, a rename) is reported as an `mcp` gap. Gemini: `${VAR}` passes through (docs support `$VAR` and `${VAR}`). Cursor: `${VAR}` is rewritten to `${env:VAR}` in every server string (command, args, env, url, headers).
- Cursor reads `AGENTS.md` itself (official docs), so `.cursor/rules/tempa.mdc` is no longer generated; `tempa sync` deletes an old copy unless it was edited by hand (per the lock).
- `tempa` server: `tempa sync` adds `tempa` (`command = "tempa"`, `args = ["mcp"]`) to all six MCP configs above at render time, unless `[mcp] serve = false` or `.tempa/mcp.toml` already has a server named `tempa`. It is not written to `.tempa/mcp.toml`, and `tempa import` does not absorb it. Claude: `.claude/settings.json` gets `enabledMcpjsonServers: ["tempa"]` so the project server needs no manual approval. Codex loads `.codex/config.toml` only in trusted projects. Commands and subagents an agent does not support (gaps in `tempa doctor`) are available through `tempa_context`.
- Copilot: VS Code (since 1.144) uses the same Copilot harness as the CLI, so the targets follow the CLI/harness format, not `.vscode/mcp.json` and `.prompt.md` (the legacy Local harness). Copilot CLI also reads `.claude/skills/` and `.mcp.json`; with Claude enabled, the same skills and servers are visible from two places with identical content. Visual Studio, JetBrains and Xcode chat read only `.github/copilot-instructions.md`, so they get no context; `tempa doctor` still reports that file as legacy, to be moved into AGENTS.md.
